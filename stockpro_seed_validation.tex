\section{Objectif du jeu de donnees}

Ce document propose un jeu de donnees seed complet pour valider les principales fonctionnalites de l'application StockPro. Les donnees sont inspirees d'un contexte industriel pharmaceutique : matieres premieres, excipients, articles de conditionnement, produits finis, fournisseurs, zones de stockage, mouvements, approvisionnement, MRP, nomenclatures, utilisateurs, alertes et rapports.

\begin{note}
La partie magasin doit conserver le libelle \textbf{Editeur Plan}. L'ancien libelle \textit{Editeur Plan Magasin} peut etre simplifie dans l'interface pour eviter un nom trop long.
\end{note}

\section{Regles generales de validation}

\begin{itemize}
  \item Les unites discretes comme boite, piece, flacon, carton et palette doivent accepter uniquement des quantites entieres.
  \item Les unites continues comme kilogramme, gramme, litre et millilitre peuvent accepter des quantites decimales.
  \item Une matiere premiere doit avoir une seule methode principale d'approvisionnement.
  \item Le Kanban est une vue de visualisation, pas une methode d'approvisionnement.
  \item Le MRP utilise les nomenclatures uniquement pour les matieres configurees en methode MRP.
  \item Les commandes doivent etre generees par le planificateur et validees ensuite.
  \item Le planificateur doit eviter les doublons lors de plusieurs lancements successifs.
\end{itemize}

\section{Donnees pour rapports et validations}

\subsection{Rapport ABC}

Pour valider l'ABC, utiliser les valeurs suivantes :
\begin{itemize}
  \item MP-API-001 et MP-API-002 doivent etre classes en A ou B selon la valeur totale.
  \item Les articles de conditionnement a grand volume peuvent apparaitre en B.
  \item Les consommables comme les gants peuvent apparaitre en C.
\end{itemize}

\subsection{Rapport stock}

Le rapport stock doit montrer :
\begin{itemize}
  \item total matieres actives : 12 ;
  \item ruptures matieres : au moins 1 ;
  \item alertes critiques : plusieurs articles sous seuil ;
  \item valeur de stock coherente avec prix unitaire et quantite.
\end{itemize}

\subsection{Rapport MRP}

Le rapport MRP doit distinguer :
\begin{itemize}
  \item les composants planifies par MRP ;
  \item les composants presents dans la nomenclature mais geres par une autre methode ;
  \item les besoins nets ;
  \item les propositions a valider.
\end{itemize}

\section{Tests de validation a realiser avec ce seed}

\begin{enumerate}
  \item Verifier que le tableau de bord affiche les alertes et ruptures.
  \item Verifier que la liste des matieres affiche les filtres par methode, statut et categorie.
  \item Lancer le planificateur une premiere fois : des propositions doivent etre creees.
  \item Relancer le planificateur : aucune proposition doublon ne doit etre creee.
  \item Valider une proposition : elle doit devenir un bon de commande.
  \item Ouvrir les bons de commande : les bons valides et envoyes doivent etre visibles.
  \item Lancer un calcul MRP pour PF-PARA-500.
  \item Verifier que les besoins sont calcules a partir de la nomenclature.
  \item Verifier que les mouvements modifient correctement les stocks.
  \item Verifier que les quantites discretes refusent les decimales.
  \item Verifier que l'Editeur Plan affiche les zones, rayons et affectations.
  \item Verifier que la suppression d'un rayon contenant du stock est bloquee.
\end{enumerate}

\section{Remarques pour implementation en seed Django}

Le fichier seed Django pourra etre implemente sous forme de commande de gestion, par exemple :

\begin{verbatim}
python manage.py seed_demo_data
\end{verbatim}

La commande doit etre idempotente :
\begin{itemize}
  \item utiliser get\_or\_create pour les referentiels ;
  \item mettre a jour les donnees existantes si necessaire ;
  \item ne pas creer de doublons si elle est relancee ;
  \item creer les propositions uniquement si elles n'existent pas deja ;
  \item vider ou reconstruire les donnees demo seulement avec une option explicite.
\end{itemize}
